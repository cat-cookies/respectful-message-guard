# 訊息溝通風險檢核器

版本 1.1.0。這是一個不需要後端、可直接部署至 GitHub Pages 的純靜態網站，用於管理人員、第一線工作者與服務人員在傳送訊息前，檢查職場霸凌、騷擾、跟蹤騷擾、申訴報復、對案家不禮貌及個資揭露風險，並產生可直接複製的較安全版本與逐項修改理由。

## 主要功能

- 第一頁先用民眾可理解的方式說明中華民國職場霸凌、工作場所性騷擾、一般性騷擾、跟蹤騷擾、校園事件與人事處分法制的分流。
- 使用者確認後才進入檢核頁；可勾選「在這個分頁關閉前不再顯示」，僅使用 `sessionStorage`。
- 在瀏覽器本機辨識直接辱罵、性別貶抑、羞辱式反問、威脅、解僱或排班施壓、申訴報復、公開羞辱、刻意排擠、資訊阻斷、不合理工作分派、持續聯絡暗示、對案家不禮貌、貼圖、表情符號及過度標點。
- 遮罩明顯的身分證字號、電話、電子郵件、地址、病歷號或個案編號；另提示健康與醫療資訊風險。
- 第一輪規則改寫後，再執行第二輪「防漏掃描」。若建議版本仍含明顯辱罵、性別羞辱、威嚇或典型嘲弄，直接捨棄殘留內容並改用中性模板，避免把危險原句再次輸出。
- 不使用後端、資料庫、API、雲端模型、分析追蹤、Cookie、CDN 或第三方 JavaScript。

## GitHub Pages 部署

1. 建立或開啟 GitHub repository。
2. 將本資料夾內所有檔案上傳至 repository 根目錄；`index.html` 必須直接位於根目錄。
3. 到 `Settings` → `Pages`。
4. `Build and deployment` 選 `Deploy from a branch`。
5. Branch 選 `main`，資料夾選 `/ (root)`，儲存。
6. 等待 GitHub Pages 完成部署。

不需要環境變數、存取權杖或後端網址。

## 本機預覽

```bash
python -m http.server 8000
```

再開啟 `http://localhost:8000`。

## 規則測試

需要 Node.js 時可直接執行：

```bash
node tests.js
```

目前測試包含：直接辱罵、性別辱罵、拆字變體、解僱威嚇、申訴報復、排擠孤立、資訊阻斷、不合理工作分派、性意味訊息、跟蹤式持續聯絡、個資遮罩、表情符號，以及合理人事程序與正常服務界線的反向測試。

## 安全設計

- `Content-Security-Policy` 的 `connect-src` 設為 `none`，阻止頁面建立外部網路連線。
- 所有 CSS、JavaScript 與內容均為本地檔案。
- 原始訊息與結果只存在目前頁面記憶體；重新整理或關閉後消失。
- 唯一儲存項目是說明頁顯示狀態，且僅使用 `sessionStorage`。
- 使用 Unicode NFKC 正規化與零寬字元清理，降低以全形、拆字或隱藏字元繞過規則的機會。
- 採小型規則引擎，不下載大型模型，也不持續背景運算。
