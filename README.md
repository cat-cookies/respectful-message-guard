# respectful-message-guard

純前端、零後端、零上傳的「訊息溝通與工作要求風險檢核器」，可直接部署至 GitHub Pages。

## 版本 1.6.0 的核心修正


### 0. 語言學風險層重構：不再只靠關鍵字

1.6.0 在既有 1,871 筆詞彙與工作情境規則之外，新增兩個離線判讀層：

- **語言學結構規則**：辨識智力羞辱、動物化、存在價值否定、咆哮驅逐、職涯／薪資威脅、申訴報復、煤氣燈、假面指導、集體孤立、造謠、公審、超密度監控、去技能化、資訊封鎖、性騷擾、性別刻板、孕產歧視、疾病污名、身分歧視、隱私刺探與數位騷擾等。
- **完整案例相似語句層**：將使用者提供的三份案例資料整理、去重與繁體中文正規化後，建立 1,349 筆完整案例；以字元 n-gram 相似度補捉同義改寫與較隱性的權勢語態。

因此目前不是「黑名單命中就算高風險」的單層做法，而是：**詞彙 → 語言學結構 → 完整案例相似度 → 工作要求合理性 → 最終輸出防漏**。

使用者實際案例「白癡／豬都比你／公司的累贅／全公司最爛／滾出去／不想要薪水」在 1.5.0 曾出現 0 命中；1.6.0 回歸測試已能同時辨識智力羞辱、動物化、存在價值否定、情緒驅逐與薪資威脅，並由完整案例語料補強。

### 1. 潤稿引擎重構：不再把表單欄位逐項貼回

1.5.0 起新增獨立 `rewrite-engine.js`；1.6.0 再加入目的導向語序規劃與內容保留檢核。潤稿與風險檢核分離，輸出改採「候選句生成＋自然度排序」：

- 依對方身分、溝通目的、溝通強度與文字風格重新安排語序。
- 提供「自然工作訊息／精簡直接／正式書面」三種風格，右側可直接切換比較。
- 新增「內容保留檢核」，檢查主題、客觀事實、行動、期限與原因是否仍出現在目前版本。
- 期限直接併入行動句，不再輸出 `處理或回覆期限：`。
- 原因不只改成因果句，會優先與「行動＋期限」融合，避免出現「避免……。」「供……。」等碎裂短句。
- `工作必要性／職務依據` 預設只供合理性檢核，不再自動塞進對外訊息。
- 內建自然度評分，淘汰 `說明如下`、重複「請」、欄位標籤式文字、不自然殘句及過度公文化候選。
- 增加語序修復：例如「後續請……」而非「請後續……」、「後續可由個案管理師……」而非「麻煩您由……」，並將自然版的「尚未／尚缺／此項／予以確認」等書面詞彙轉為一般工作用語。
- 拒絕或服務界線類訊息，優先採「客觀限制／原因 → 替代處理方式」，避免只把拒絕寫得更冷硬。
- 潤稿仍不接受原始訊息，不會用辱罵原文猜測或補寫事實。

### 2. 不只看語氣，也檢查「工作要求本身」

工作內容合理性引擎會先檢查工作要求本身是否合理；1.4.0 另在此基礎上大幅擴充離線近義詞與常見變體，先檢查：

- 陪酒、強制飲酒、續攤。
- 私人差事或與職務無合理關聯之要求。
- 社交宴會、餐敘、陪同見面但欠缺具體工作必要性。
- 不合理工作量、與能力明顯不符的工作、故意給不足資源。
- 下班後無限待命、不得漏接電話或訊息。
- 請假刁難、申訴後解僱／降調／減薪／不排班等報復。
- 刻意排除必要會議、資訊或資源。
- 偽造、回填不實、刪改紀錄。
- 規避安全程序、資格、查核或必要通報。
- 性要求、性別角色要求、外貌或身體條件要求。
- 權勢關係下要求進入私人房間、旅館等高風險情境。

若要求本身屬阻擋型高風險，網站**不會幫它潤飾**，而是直接不提供可複製版本。

### 3. 「工作必要性／職務依據」改為安全判讀欄位

模糊的社交、餐敘、休息時間活動等，不宜僅靠詞彙決定。使用者可補充具體職務依據，例如專案、客戶會議、服務流程、法定義務、SOP、輪值或研究／醫療／教育需求。

「因為我是老闆」、「主管說了算」、「照做就對」等不視為工作必要性，也不能解除阻擋。

### 4. 離線語料庫與來源索引

`risk-corpus.js` 與 `expert-corpus.js` 目前包含：

- 1,871 筆逐筆高風險用語／近義詞／常見變體。
- 1,349 筆繁體中文完整案例相似語料。
- 11 組既有上下文／語句結構規則，加上 1.6.0 語言學結構規則。
- 17 組既有工作內容合理性規則，加上 1.6.0 高風險工作語言學阻擋規則。
- 17 組法規、主管機關指引／FAQ、司法實務來源索引。

每筆用語均一對一配對：唯一語料代碼、風險類別、嚴重度、警示、較安全處理方式、法制標籤及來源代碼。

例如「肛交」已納入明確性行為詞彙；一般管理／社交情境會攔截，若確屬醫療、法律、教育或研究的必要專業術語，則須有明確專業職務依據才可保留，並仍顯示情境提醒。


### 5. 近義詞與常見變體擴充

1.4.0 不是單純追加髒話清單，而是以既有風險類型為中心，補入合理範圍內的：

- 直接近義詞與同義改寫。
- 臺灣常見口語、俗語及工作場合常見說法。
- 性／身體用語的委婉詞與代稱。
- 常見字形、同音及網路語言變體。
- 不合理工作分派、申訴報復、下班待命、不實紀錄、安全程序規避等管理語句。

為降低誤判，高度多義的中性詞原則上不單獨列入，而改採較完整短語；新增高風險工作內容近義表達也同步擴充工作情境阻擋規則。

### 6. 原始訊息與輸出徹底分流

原始訊息只供風險掃描。右側建議版本只由使用者另填的實質工作內容產生；`composeSafeMessage()` 不接受原始訊息參數。

### 7. 多層防漏

1. 原始訊息：詞彙、語言學結構與完整案例相似度掃描。
2. 實質工作內容：同一套語言風險掃描。
3. 工作要求合理性：跨欄位檢查工作本身，而非只看語氣。
4. 建議版本完成後再掃描一次，避免高風險文字重新進入輸出。

只要仍有阻擋型內容，`copyable=false`，不提供可複製文字。

## 純前端與資訊安全

- 無後端、無帳號、無伺服器資料庫。
- 無API、無雲端模型、無第三方 JavaScript。
- 無分析追蹤、無 Cookie。
- 不使用 fetch、XMLHttpRequest 或 WebSocket。
- CSP 設定 `connect-src 'none'`。
- 使用者文字與分析結果不寫入 localStorage、IndexedDB 或檔案。
- 僅使用 sessionStorage 記錄「本分頁是否略過法制說明」，關閉分頁後失效。

## 本機測試

需安裝 Node.js：

```bash
node --check risk-corpus.js
node --check rewrite-engine.js
node --check app.js
node --check tests.js
node tests.js
```

1.5.0 測試除原有法律風險與語料回歸外，另包含：

- 「肛交」必須命中離線語料。
- 「晚上陪酒＋社交宴會＋陪主管與其他老闆見面」在欠缺合法合理職務依據時必須阻擋輸出。
- 「因為我是老闆」不得解除阻擋。
- 具體專案客戶餐敘、有清楚工作必要性且明示飲酒／續攤非必要可拒絕時，可降為情境提醒。
- 專業醫療／法律／教育／研究中的必要敏感術語可在具體專業依據下保留。
- 非專業情境的明確性行為要求必須阻擋。
- 偽造紀錄、規避安全、下班後無限待命、不合理工作分派必須阻擋。
- 原始訊息不得進入輸出。
- 實質內容二次攔截、最終防漏、個資遮罩、符號拆字。
- 語料代碼唯一性、來源代碼完整性與來源索引完整性。


- 自然版不得再出現 `說明如下`、`相關原因、影響或程序：`、`工作必要性或職務依據：` 等欄位模板。
- 「職務依據」預設不得出現在對外訊息，只有明確勾選才可納入。
- 自然／精簡／正式三種輸出必須實質不同。
- 對案家／服務對象須使用合適敬稱與自然語序。
- 自然度評分器必須使一般自然句分數高於典型表單／公文拼接句。
- 「避免／確保／方便／供後續使用」等原因必須與前句自然銜接，不得形成碎裂句。
- 「後續」工作指示、第三方處理與拒絕型訊息必須通過專門語序回歸測試。

目前測試：1,871 筆詞彙＋11 組結構規則＋17 組工作情境規則＋17 組來源索引，全部通過。

## GitHub Pages 部署

將本資料夾所有檔案放在 repository 根目錄，再設定：

`Settings → Pages → Deploy from a branch → main → /(root)`

不需要後端網址、Token、環境變數或 GitHub Actions。

## 使用邊界

本工具是送出訊息或下達工作要求前的風險控制工具，不是自動法律裁判器。是否成立職場霸凌、性騷擾、跟蹤騷擾、侵權、犯罪或勞動法違法，仍須依完整事實、權勢關係、工作必要性、頻率、影響、證據與法定程序判斷。
